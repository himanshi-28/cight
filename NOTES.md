# Teaching Notes

- The learner identifies as a beginner with mostly theoretical knowledge.
- Use CIght as the persistent practice system rather than unrelated toy examples.
- Work ticket by ticket; do not provide the complete implementation before an attempt.
- Explain concepts in plain language, then require a prediction or design choice.
- Review attempts directly for correctness, security, naming, edge cases, testing, and production tradeoffs.
- Target independent mid-level reasoning, while being explicit that simulated exercises do not replace real production experience.
- Treat CI/CD as completely new material: begin with vocabulary, predictions, and tracing before assigning YAML or deployment changes.
- Assign the learner the smallest safe ticket first, then increase implementation complexity only after they can explain the previous layer.
