# Mission: Java and Spring Boot Interview Readiness Through CIght

## Why

Use CIght to become capable of earning and succeeding in a Java/Spring Boot backend role. The learner has two years of software experience but limited backend production exposure, so the project must turn theoretical familiarity into implementation, debugging, testing, system-design, and interview-defence ability.

## Success looks like

- Independently deliver and test a Spring Boot feature across HTTP, service, persistence, and infrastructure boundaries.
- Explain Core Java, Spring, JPA, PostgreSQL, Docker, Kafka, security, caching, and CI/CD decisions at a two-to-three-year backend interview level.
- Diagnose failures using tests, logs, database inspection, container tooling, and small experiments.
- Design CIght as a modular monolith and defend its data model, consistency, delivery, scaling, and failure-mode tradeoffs.
- Build and compare baseline, RAG, and agentic failure analysis with bounded tools and grounded evidence.
- Expose safe read-only capabilities through MCP and demonstrate the complete system through Codex.

## Constraints

- Six weeks at approximately 12–15 focused hours per week.
- One learner-owned ticket at a time, normally 90–120 minutes.
- Java practice stays inside CIght rather than using a separate algorithm track.
- The learner predicts and attempts implementation before receiving a complete solution.
- Existing Codex-generated code is reference material, not evidence of learner understanding.
- Live AI and external-service calls are manual demonstrations; automated tests and CI use fakes or local infrastructure.

## Out of scope

- Frontend implementation.
- Standalone DSA preparation during this six-week path.
- Kubernetes, Terraform, or production-grade cloud operations.
- Premature microservice extraction.
- Claiming generated or unexplained code as learned experience.
