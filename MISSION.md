# Mission: Spring Boot Backend Engineering Through CIght

## Why
Build CIght into a production-minded CI/CD observability platform while developing the judgment and hands-on ability expected of an independent backend SDE. The goal is to move from knowing concepts in theory to designing, implementing, testing, debugging, and defending real engineering decisions.

## Four-week objective

Complete a portfolio-ready CIght backend within four weeks at approximately 12–15 focused hours per week.

The finished system must include reliable Spring Boot APIs, PostgreSQL, signed GitHub workflow ingestion, transactional Kafka processing, baseline Gemini analysis, agentic Gemini analysis with bounded read-only tools, and a local read-only MCP integration that Codex can use.

Success requires both working software and demonstrated understanding. Existing code does not count as learned until the user can explain, test, debug, or defend it.

## Success looks like
- Independently deliver a Spring Boot feature from requirements through tested API behavior
- Design relational data models and queries while explaining correctness and performance tradeoffs
- Debug failures systematically using logs, tests, database inspection, and small experiments
- Build and operate a secure, observable service using Docker, CI/CD, messaging, caching, and authentication
- Trace a failed GitHub workflow through the webhook, database, outbox, Kafka, Gemini analysis, REST API, and MCP
- Compare baseline and agentic AI analysis and explain when bounded tool use adds value
- Explain monolith, microservice, AI-agent, and MCP design choices at a three-year-SDE interview level

## Constraints
- Complete the critical roadmap within four weeks at approximately 12–15 focused hours per week
- Learn through one CIght ticket at a time
- Explain why and the underlying concept before implementation
- The learner attempts the code before receiving a complete solution
- Use retrieval practice, tests, and PR-style review instead of passive reading
- Current foundation is basic Spring Boot and SQL theory with limited production practice

## Out of scope
- Frontend implementation until the backend foundation and API contracts are stable
- Premature microservice extraction before the monolith is tested and understood
- Copying complete solutions without first making and defending an implementation attempt
